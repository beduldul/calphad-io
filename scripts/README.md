# The pycalphad cross-check

The README claims that **pycalphad reads the files `calphad-io` writes as
identical to the originals** — same elements, species, phases, sublattice
constituents, model hints and every parameter expression — for all 25
regenerated databases. These two scripts make that claim checkable, end to end,
by anyone.

`calphad-io` does not depend on pycalphad, and neither does its test suite: the
cross-check is an *external* verification, so it lives here and is run by hand.

## What it proves

* `generate.py` round-trips every real database in `tests/data/` through
  `calphad-io`'s own reader and writer. This is the step that produces the
  "regenerated" corpus. It is the half that was missing: without it the
  comparison has no inputs.
* `verify.py` loads each original and each regenerated file with **pycalphad's
  own `Database`** and compares a structural fingerprint of the two. pycalphad
  is an independent implementation — it shares no parsing code with
  `calphad-io` — so agreement is evidence that the output is a faithful
  database, not merely that the writer is self-consistent.

The fingerprint covers: elements, species, phases and their sublattice
constituents, model hints, and every parameter (`phase_name`, `parameter_type`,
`parameter_order`, `constituent_array`, `parameter`, `tzero`).

`FeMnCaS-1.dat` is excluded because `calphad-io` refuses it by design (it uses
the `SUBI` model, which pycalphad cannot read either). That leaves 25 of the 26
fixtures.

## Setup

`verify.py` needs pycalphad, which must **not** be installed into `calphad-io`'s
own virtualenv — that virtualenv is the "zero dependencies" claim. Use a
separate one:

```bash
# a throwaway virtualenv just for the comparison
python -m venv /tmp/calphad-refenv
/tmp/calphad-refenv/bin/pip install pycalphad

# calphad-io's own virtualenv, for the generator
python -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

## Running it

```bash
# 1. regenerate every fixture with calphad-io itself
.venv/bin/python scripts/generate.py --out /tmp/calphad-roundtrip

# 2. compare the regenerated files with the originals, using pycalphad
/tmp/calphad-refenv/bin/python scripts/verify.py tests/data /tmp/calphad-roundtrip
```

Both scripts take the directories as arguments; nothing is hardcoded to `/tmp`.
`generate.py` defaults its first argument to `tests/data/`, and `--help` on
either script explains the rest.

## Expected output

`generate.py`:

```
SKIPPED FeMnCaS-1.dat: refused by design (phase model)

GENERATED=25 SKIPPED=1 FAILED=0
```

`verify.py`:

```
pycalphad 0.11.2
not regenerated by calphad-io (1): FeMnCaS-1.dat

IDENTICAL=25 DIFFERS=0 SKIPPED=0
```

`DIFFERS=0` is the claim. `SKIPPED=0` means pycalphad could read every file it
was given. The `not regenerated` line names the file `calphad-io` refused; it is
reported separately rather than counted as a skip, because the skip counter is
about pycalphad, not about `calphad-io`.

Exit codes: `generate.py` returns 1 if a fixture could not be regenerated,
`verify.py` returns 1 if any file differs or pycalphad could not read a
regenerated file, and both return 2 on bad usage (including pycalphad not being
importable).

## What this does *not* prove

Correctness against **FactSage** is not established here, and cannot be: that
is the same blocker the pycalphad maintainer named in
[pycalphad#413](https://github.com/pycalphad/pycalphad/issues/413). pycalphad
reading a file as identical means the model survived the write, not that
FactSage would accept the layout.
